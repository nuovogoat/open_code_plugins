# opecode-model-autorouter

Серверный плагин OpenCode V2 для маршрутизации между эквивалентными chat-моделями разных провайдеров. Учитывает фактические скорость и стоимость завершённых шагов, приоритет бесплатных моделей и временную недоступность после ошибок лимита.

## Возможности

- Автоматически сканирует включённые модели подключённых провайдеров и повторяет сканирование после изменений конфигурации. Запрос `model.list` ограничен типом `chat`.
- Автоматически объединяет только модели с одинаковым `id` у разных провайдеров. Совпадения display name и неоднозначные псевдонимы не объединяются.
- Поддерживает ручные группы с разными model ID и `variant`, приоритетом моделей и отдельной стратегией для каждой группы.
- Собирает в памяти TTFB HTTP-ответов, длительность шагов, скорость генерации, фактические `cost` и `tokens`. Для скользящих средних используется `metricAlpha`.
- Распознаёт `402`, `429` и типовые quota/billing/rate-limit ошибки, помещает модель на cooldown и выбирает альтернативу.
- После лимита может автоматически продолжить существующую задачу через synthetic-сообщение, не отправляя пользовательский prompt повторно.
- Предоставляет RPC `status`, `rescan` и `select`.

## Установка и обновление

```sh
opencode plugin add 'github:nuovogoat/open_code_plugins#main::path:opecode-model-autorouter'
opencode plugin check
opencode plugin update
```

Фиксированная версия:

```sh
opencode plugin add 'github:nuovogoat/open_code_plugins#opecode-model-autorouter/v0.1.0::path:opecode-model-autorouter'
```

История версий: [CHANGELOG.md](CHANGELOG.md).

Для локальной разработки укажите каталог плагина в `opencode.jsonc` либо поместите его в `.opencode/plugins/` проекта или `~/.config/opencode/plugins/`. Не подключайте одновременно две копии с одинаковым ID.

## Настройка

Параметры передаются через объектную форму записи в `opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "./opecode-model-autorouter",
      "options": {
        "enabled": true,
        "autoDiscover": true,
        "strategy": "free-fastest",
        "cooldownMs": 60000,
        "resumeAfterFailover": true,
        "metricAlpha": 0.25,
        "rescanIntervalMs": 60000,
        "groups": {
          "kimi": {
            "strategy": "free-fastest",
            "models": [
              "apimaster/kimi-k3.1-pro",
              "openrouter/moonshotai/kimi-k3.1-pro",
              { "providerID": "plusvibe", "id": "kimi-k3.1-pro", "variant": "max" }
            ]
          }
        }
      }
    }
  ]
}
```

Ручная группа применяется, если текущая модель сессии входит в неё. Необязательный `defaultGroup: "kimi"` направляет в эту группу каждый prompt, включая сессии с первоначально посторонней моделью.

Строковая ссылка имеет формат `providerID/modelID` или `providerID/modelID#variant`. Model ID может сам содержать `/`: первый `/` отделяет провайдера. Недоступные и отключённые модели в группу не попадают. Автоматические группы работают с базовой моделью и распознают её при выбранном variant; перечисление отдельных variant поддерживается в ручных группах.

### Стратегии

- `free-fastest` — сначала бесплатные модели, затем наибольшая измеренная скорость генерации, меньшие TTFB и latency. Модели без известной нулевой цены не считаются бесплатными.
- `fastest` — скорость независимо от стоимости.
- `cheapest` — фактическая стоимость на миллион сгенерированных токенов; до появления измерений используется каталожная цена.
- `manual` — порядок `models` в конфигурации; метрики не меняют приоритет.

До первых измерений стратегии скорости исследуют неизвестные модели. В автоматических группах альтернатива не должна уменьшать доступный context window и должна сохранять поддержку tools, если она нужна текущей модели. Для ручной группы context window считается явным выбором пользователя, но совместимость tools сохраняется.

## Failover и его ограничения

После ошибки лимита текущая модель исключается на `cooldownMs` или на серверный `Retry-After`. Каждая альтернатива перебирается не более одного раза в рамках автоматического выполнения. Новый prompt пользователя, успешное/прерванное выполнение, удаление сессии и cleanup отменяют соответствующее ожидающее продолжение.

При `resumeAfterFailover: true` плагин ждёт завершения неудачного execution и отправляет synthetic-продолжение по уже существующей истории. Это **не бесшовное соединение токенов уже начатого потока**: стандартный API такого продолжения не гарантирует. Модель получает инструкцию использовать историю и не повторять завершённые side effects, но автоматический анализ выполненных действий всё равно необходим.

При `resumeAfterFailover: false` модель переключается без synthetic-продолжения и без отмены штатного retry OpenCode.

Метрики и cooldown хранятся только в памяти процесса и сбрасываются при перезапуске. Плагин не обходит квоты и не создаёт новые учётные данные или подписки.

## RPC

- `status` — группы, доступность, cooldown и метрики без prompt, ответов, ключей и путей.
- `rescan` — немедленно повторяет обнаружение и возвращает `status`.
- `select` — принимает `{ "sessionID": "…", "model": "provider/model#variant" }` и явно выбирает модель из настроенных групп.

Например, через HTTP API текущего сервера (каталог проекта подставляется в `location[directory]`):

```sh
opencode api post '/api/rpc/opecode-model-autorouter/status?location%5Bdirectory%5D=C%3A%5Cpath%5Cto%5Cproject' --data '{"input":{}}'
```

Ответ находится в поле `output`. Те же методы доступны через `ctx.rpc` и `@opencode/client` без ручного формирования HTTP-обёртки.

## Тесты

Нужен Node.js 22.18+:

```sh
npm test
npm run test:memory
```

`test:memory` запускает 3000 циклов setup/cleanup с `--expose-gc` и проверяет освобождение hook/RPC-регистраций, подписок и ограниченную дельту heap.

Проверка с фактически установленным SDK:

```sh
npm install --ignore-scripts
npm run test:sdk
```

`test:live` использует `OPENCODE_CLI`, загружает плагин только для временного тестового проекта и проверяет обнаружение/RPC без отправки prompt провайдерам.
