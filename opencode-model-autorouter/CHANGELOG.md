# Журнал изменений

Плагин использует [Semantic Versioning](https://semver.org/lang/ru/). Каждый релиз помечается Git-тегом `opencode-model-autorouter/vX.Y.Z`.

## [0.12.0] - 2026-11-01

### Добавлено

- Секция GUI «Справка» и строка «О плагине» (соответствие канону v2.19, §6.11 и §10): содержательная справка — сценарии (подключение аккаунта, ручной выбор модели и ответы на вопросы защиты, подсчёт затрат, ограничение дорогих моделей и бедных аккаунтов, смена стратегии, сброс), последствия действий и граничные случаи; атрибуция «by nuovogoat» и версия продукта из единого источника (`package.json`, инжекция подстановкой vite `define` — дубль литерала версии в `src/` запрещён гейтом). Описания полей сетки настроек и фильтров каталога дополнены раскрытием «чем грозит изменение» (критерий §6.11 v2.19: пояснение отвечает на два вопроса — что делает поле и чем грозит его изменение). Отклонения, неотъемлемые от встроенной панели (меню первого уровня и окна принадлежат хосту OpenCode Desktop; §6.10 не применяется — чат-контур рисует хост; core_pack — только для Python-инструментов), зафиксированы в новом `DECISIONS.md` (механизм документированных отклонений §6.4).
- Гейт: `test/version.test.ts` — «gui: bundle carries about-attribution and the single-source version» (бандл содержит атрибуцию и текущую версию; `src/gui.tsx` использует подставляемый при сборке плейсхолдер `__PLUGIN_VERSION__` вместо литерала версии; секция справки присутствует).

## [0.11.0] - 2026-11-01

### Добавлено

- Секция GUI «Статистика использования»: токены завершённых шагов сессий OpenCode (входные, выходные включая рассуждения, кэш чтение/запись) и финансовые затраты в реальном времени — по каждой сессии и итого. Основание стоимости — подтверждённый тариф аккаунта первого уровня в валюте аккаунта (токены рассуждения — по цене output; токены кэша — только если тариф объявляет цены кэша); без подтверждённого тарифа — стоимость, измеренная самим OpenCode, в USD; нет ни того ни другого — прочерк, значения не выдумываются. Разные валюты и основания не суммируются в одно число: строка «Итого» даёт сумму в разрезе валют. Статистика накапливается серверной частью из событий `session.step.ended`, ограничена 500 сессиями, очищается при удалении сессии и возвращается RPC `status` в поле `usage` (`sessions`, `totals`); GUI обновляет её вместе со статусом (порядка 30 секунд).
- Тесты: unit-тест защитного разбора токенов и тарификации только объявленными ценами тарифа; класс-уровневый тест накопления (рублёвый аккаунтный тариф, фолбэк на измеренную USD-стоимость, итоги в разрезе валют, очистка при удалении сессии); live-прогон проверяет форму `usage` на реальном CLI.

## [0.10.1] - 2026-11-01

### Исправлено

- RPC `setAccountKey` теперь отклоняет провайдеров без подтверждённого аккаунтного API (например, `apimaster`): ключи отправляются только на захардкоженные origin аккаунтных API, поэтому ключ у такого провайдера не имел бы потребителя — это мёртвая настройка, и она не принимается и не сохраняется. Проверка capability выполняется до записи в сейф и использует тот же источник истины, что и GUI (новый экспорт `accountCapable` в `pricing.ts`, обёртка над `capabilities()`); проверка roster в `vault.set` сохранена для неизвестных провайдеров и пустых ключей. Дефект существовал с момента отказа от хардкод-списков (`e679071`) и был обнаружен жёстким live-прогоном реальным CLI (`test/live-router.ts`), который не входит в герметичную сюиту. Добавлен герметичный тест: отклонение провайдера без аккаунтного API, отсутствие записи в хранилище, успешное сохранение для провайдера с подтверждённым API.

## [0.10.0] - 2026-11-01

### Изменено

- Явно включённая ориентировка по курсу ЦБ РФ (`cbrOrientation: true`) теперь участвует не только в отображении «≈», но и в ранжировании стратегии `cheapest`: цены кандидатов в разных валютах приближённо пересчитываются в рубли по официальному курсу ЦБ РФ и сравниваются численно (при равенстве цен решает измеренная скорость, как прежде). Это сознательно приближённый метод, и GUI/документация помечают его как неточный: курс ЦБ — официальный, а не курс провайдера; провайдеры конвертируют средства по своим курсам, поэтому фактические расходы могут отличаться от оценки. Пересчёт лишь упорядочивает кандидатов и не является котировкой; отображение цен всегда остаётся в исходной валюте аккаунта. Если курс хотя бы одной из валют с подтверждённой ценой не загружен (или значение некорректно), разные валюты, как и прежде, численно не сравниваются — ничего не выдумывается. Выключение флажка (по умолчанию) полностью возвращает прежнее поведение: запросы к ЦБ РФ не выполняются, смешанные валюты сравниваются нечисленно.
- Границы цены (`priceLimits`) и пороги остатка (`accountThresholds`) пересчёту не подлежат и по-прежнему проверяются строго в валюте аккаунта/цены — пересчёт влияет только на порядок кандидатов при выборе модели.

## [0.9.0] - 2026-11-01

### Добавлено

- Публичные цены без входа распознают формат шлюзов new-api/one-api: к путям обнаружения добавлен `/api/pricing` (до шести запросов на провайдера), а ответ с `data[].model_name`/`model_ratio`/`completion_ratio` конвертируется в USD за 1M токенов по конвенции one-api (500000 quota = $1; вход = `model_ratio × 2`, выход дополнительно умножается на `completion_ratio`). Конвенция проверена эмпирически на публичных данных apimaster.ai (gpt-6-astra: ratio 5 → $10/$50 за 1M — ровно цены, которые показывает сайт). Модели с поштучной тарификацией (`quota_type ≠ 0`) и строки без положительного токенного коэффициента пропускаются — цены никогда не выдумываются. Формат распознаётся по структуре ответа, а не по имени провайдера: он работает для любого шлюза семейства new-api, чей адрес указан в `providerSites`. Цены apimaster теперь доступны без входа: укажите `https://apimaster.ai` в панели «Публичные цены без входа».

### Примечания

- Аккаунтная интеграция apimaster (баланс по ключу) не реализована и не планируется в таком виде: публичный API apimaster.ai документирует только чат/модельные эндпоинты, `/api/user/self` принимает сессионный токен консоли, а `/v1/dashboard/billing/subscription` возвращает фиктивную заглушку лимита ($100M) вместо реального баланса — отображать её означало бы выдумывать цифры. Аккаунтное состояние apimaster остаётся `unsupported`; расход по ключу (`/v1/dashboard/billing/usage`) не отображается, поскольку единицы измерения ответа не документированы и не подтверждены.

## [0.8.0] - 2026-11-01

### Добавлено

- Защита ручного выбора модели (`askBeforeOverride`, по умолчанию включена): если текущая модель сессии не была установлена самим роутером (выбрана пользователем или конфигурацией вручную), роутер больше не переключает её молча на следующем prompt. Вместо этого регистрируется запрос на переключение и отправляется одно synthetic-уведомление (без resume — запрос пользователя продолжается на выбранной модели). Ответ даётся в GUI-панели «Защита ручного выбора» или через RPC: `resolveOverrideRequest` с `action: "keep"` закрепляет ручную модель за сессией (пока она закреплена и не сменена, роутер её не перемаршрутизирует и повторно не спрашивает), `action: "override"` переключает на предложенную модель и передаёт её под управление роутера. `releaseManualSelection` снимает закрепление и возобновляет автоматическую маршрутизацию. Ручной выбор через RPC `select` также закрепляет модель. Failover по лимитам провайдера по-прежнему выполняется молча с уведомлением — это аварийное переключение, а не перехват пользовательского выбора.
- `status` дополнительно возвращает `askBeforeOverride`, `overrideRequests[]` (сессия, текущая и предложенная модели, группа, время вопроса) и `pinnedModels[]` (закреплённые ручные модели сессий). `configure` принимает `askBeforeOverride`; выключение защиты очищает нерешённые запросы.
- GUI: переключатель «Защита ручного выбора модели» в настройках и панель «Защита ручного выбора» — карточки нерешённых вопросов с кнопками «Оставить …»/«Переключить на …» и закреплённых моделей с кнопкой «Снять закрепление».
- Тесты: сценарий «оставить» (вопрос вместо переключения, единственное уведомление, повторный prompt без спама, закрепление, повторный вопрос после снятия), сценарий «переключить» (переключение, отметка владения роутера, отсутствие повторных вопросов, отклонение устаревшего ответа), сценарий opt-out (`askBeforeOverride: false` — прежнее молчаливое автоматическое переключение). Существующие тесты автоматической маршрутизации явно отключают защиту опцией.

### Изменено

- Карты пер-сессионного состояния роутера (отметки владения, закрепления, вопросы) ограничены 500 записями с FIFO-выбыванием: заброшенные сессии не могут расти в памяти.

## [0.6.0] - 2026-10-31

### Добавлено

- Публичное обнаружение цен для любого провайдера без входа в аккаунт: настройка `providerSites` (или поле адреса в новой панели GUI «Публичные цены без входа») принимает адрес заглавной страницы поставщика, например `https://openrouter.ai`. Роутер проверяет до пяти стандартных путей публичного списка моделей (`/v1/models`, `/api/v1/models`, `/models`, `/api/models`; адрес, уже указывающий на список, проверяется первым) и использует первый ответ с распознанными ценами. Распознаётся только формат листов OpenRouter (`pricing.prompt`/`pricing.completion`, USD за токен → цена за 1M); списки без цен или в неизвестном формате не дают ничего — цены никогда не выдумываются.
- Запросы к указанным адресам строго неаутентифицированные: `credentials: "omit"`, без authorization/cookie, без redirect (`redirect: "error"`), таймаут 15 с и ограничение размера ответа 16 МБ. Принимаются только https-адреса (http — для localhost), встроенные в адрес credentials и невалидные URL отклоняются, слишком длинные адреса не обрезаются, а отбрасываются. Ключи аккаунтов по-прежнему отправляются только на зафиксированные в коде API-origin — настройки `providerSites` не могут перенаправить аккаунтный запрос.
- Если адрес не задан вручную, роутер best-effort извлекает его из конфигурации провайдера OpenCode (`settings.options.baseURL`, `settings.baseURL`, корневой `baseURL`); ручной `providerSites` всегда приоритетнее, а извлечённые адреса проходят ту же валидацию.
- Аккаунтный тариф всегда приоритетнее публичного: публичные цены заполняют только модели без подтверждённой аккаунтной цены. `models[].priceState` расширяется значениями `public` и `public-stale`; статус добавляет `providerSites` и снимки `publicPricing[]` (провайдер, точный endpoint-источник, состояние, время загрузки, признак устаревания, число моделей с публичной ценой). `accounts[].matchedModels` считает только аккаунтные цены (`live`/`stale`).
- Кэширование публичных цен ~6 часов на провайдера, повторная попытка после ошибки — через ~30 минут; при ошибке последний удачный снимок сохраняется с пометкой `stale` и никогда не выдаётся за свежий. При удалении адреса снимок провайдера удаляется, параллельные запросы ограничены четырьмя провайдерами, глобальные границы цены `priceLimits` применяются и к публичным ценам.
- GUI: панель «Публичные цены без входа» со строкой на каждого провайдера каталога — поле адреса, кнопки «Сохранить адрес»/«Удалить адрес», бейдж «публичный тариф · N моделей» с точным endpoint в подсказке и кнопка «Войти для точных расходов» (открывает форму ключа сейфа) для провайдеров с аккаунтным API. Подписи цен моделей дополнены состояниями `public`/`public stale`.
- Тесты: валидация адресов (схемы, credentials, мусор, сверхдлинные URL), извлечение `baseURL`, порядок и ограничение endpoint-кандидатов, распознавание только формата OpenRouter, анонимность и порядок запросов загрузчика, отклонение oversized-ответов, abort «висящего» endpoint, приоритет аккаунтной цены и `public-stale`-кэш, e2e через RPC (заполнение цен, кэш в пределах TTL, границы цены для публичных цен, очистка адресов останавливает запросы). Новый `test/robustness.test.ts`: мусорные и `__proto__`-ключи в настройках, абсурдные configure-patch'и, враждебный fetch (синхронные/асинхронные падения, битый JSON, 500, oversized content-length), cleanup во время in-flight discovery без unhandled rejections, churn из 200 адресов с ограниченным числом снимков и 500 циклов discovery с `--expose-gc` без неограниченного роста heap. Live-тест проверяет публичное обнаружение цен OpenRouter без входа, отклонение невалидного адреса и очистку снимков.

### Изменено

- Нормализация настроек дополнительно защищает записи `groups`, `accountThresholds`, `priceLimits` и `providerSites` от ключа `__proto__`; `providerSites` ограничены 50 записями.

## [0.5.0] - 2026-10-31

### Добавлено

- Мониторинг минимального остатка: `accountThresholds` задаёт для каждого провайдера минимальный остаток `minBalance` в валюте самого аккаунта. Действие `action: "warn"` только помечает (бейдж «ниже минимума» в GUI и поле `lowBalance` в RPC-статусе), `action: "exclude"` дополнительно исключает модели провайдера из выбора роутера и ручного `select` (`thresholdExcluded`). Исключение снимается автоматически на следующем обновлении, когда остаток вернётся в норму.
- Глобальные границы цены `priceLimits`: для каждой валюты аккаунтных цен (например `USD`, `RUB`) задаются верхние и нижние границы цены за 1M токенов — `inputMax`/`outputMax` и `inputMin`/`outputMin` (input и output первого тарифа, как в каталоге). Границы применяются сразу ко всем моделям всех провайдеров с подтверждённым аккаунтным тарифом в этой валюте; значения в разных валютах никогда не смешиваются. `action: "warn"` только помечает (бейдж «вне границ цены» в GUI, поле `priceLimitBreached` в RPC-статусе), `action: "exclude"` убирает модели вне границ из роутинга — автопереключение на допустимые модели происходит при следующем выборе (prompt, failover, стратегия `cheapest`, ручной `select` отклоняется). Исключение снимается автоматически, когда цена вернётся в границы. Модели без подтверждённого аккаунтного тарифа по цене не помечаются и не исключаются.
- Необязательная ориентировка по курсу ЦБ РФ (флажок «Ориентировка по курсу ЦБ РФ», `cbrOrientation` в настройках): серверная часть запрашивает официальное публичное ежедневное API ЦБ РФ (`www.cbr.ru/scripts/XML_daily.asp`) без передачи каких-либо credentials, парсит курсы без зависимостей и кэширует их ~6 часов (повторная попытка после ошибки — через ~15 минут). GUI показывает приблизительные эквиваленты «≈» балансов и цен во всех валютах, в которых представлены цены и балансы аккаунтов, с датой курса и пометкой об устаревании. Курсы используются только для отображения: маршрутизация, стратегия `cheapest` и сравнение цен работают как раньше — разные валюты не сравниваются численно. При выключенном флажке дополнительные сетевые запросы не выполняются; при недоступности API ориентировка просто не показывается и ничего не выдумывается.
- Форма порогов в панели «Аккаунты провайдеров»: минимальный остаток в валюте аккаунта, выбор действия «только предупреждать» или «предупреждать и исключать из роутинга», сводка заданных порогов у каждого аккаунта. Отдельная панель «Границы цены для всех моделей»: строка на каждую валюту аккаунтных цен с полями input ≤ / output ≤ / input ≥ / output ≥, выбором действия и сохранением.
- Тесты: парсер ежедневного XML ЦБ РФ (VunitRate/Nominal/запятые как разделители, битые записи пропускаются), загрузчик курсов (фиксированный origin, отсутствие authorization, отклонение распознанных иначе лент), чистая функция `evaluateGuardrails` (остатки в валюте аккаунта, границы цены сразу для всех провайдеров одной валюты, нижние границы, чужие валюты не сравниваются), e2e через RPC роутера (warn не меняет выбор, exclude по остатку и по границе цены перенаправляет prompt и блокирует `select`, восстановление автоматически, кэш курсов в пределах TTL, ноль запросов при выключенном флажке), кросс-курсы и список валют ориентировки в GUI-каталоге; live-тест проверяет конфигурацию/сброс порогов и границ цены и толерантно — доступность ленты ЦБ РФ.

### Изменено

- `buildRouteGroups` принимает дополнительный набор исключённых порогом моделей; `status` дополнительно возвращает `accountThresholds`, `priceLimits`, `cbrOrientation`, блок `cbr` (дата, время загрузки, признак устаревания, курсы), `accounts[].lowBalance`, `models[].priceLimitBreached` и `models[].thresholdExcluded`. Семантика `routingEnabled` не изменилась: это по-прежнему только пользовательский переключатель.

## [0.4.0] - 2026-10-31

### Добавлено

- Необязательный сейф аккаунтных ключей плагина для OpenRouter, TeamoRouter и PlusVibe: ключ задаётся через GUI или RPC `setAccountKey`, шифруется AES-256-GCM в server storage плагина и отправляется только в аккаунтный API своего провайдера. Ключ не передаётся OpenCode, не отображается в GUI, не возвращается через RPC и не попадает в статус; `clearAccountKey` удаляет ключ и возвращает роутер к connections OpenCode. Сейф не обязателен: источник ключей по умолчанию — сохранённые в OpenCode connections.
- Панель «Аккаунты провайдеров» показывает источник активного ключа (бейдж «ключ плагина» или «ключ OpenCode»), кнопки «Задать/Заменить ключ» и «Удалить ключ» и маскированную форму ввода. Провайдеры с подтверждённым аккаунтным API перечислены даже без подключения в OpenCode, чтобы ключ можно было задать в любой момент.
- Тесты сейфа: roundtrip, шифрованное хранение, повреждённые записи, удаление, отклонение провайдеров без аккаунтного API, e2e через RPC роутера и синхронизация списка провайдеров между vault, RPC-схемой и GUI-каталогом.

### Изменено

- Ключ из сейфа плагина имеет приоритет над ключом из connections OpenCode: сохранение ключа в плагине — явный выбор пользователя.
- Состояние `stale` больше не показывает источник ключа, если credential перестал разрешаться.
- Хранилище сейфа ничего не записывает при запуске роутера: соль шифрования сохраняется только вместе с первым ключом.

## [0.3.0] - 2026-10-31

### Добавлено

- Аккаунтные тарифы и остаток средств из API провайдеров: OpenRouter (`/models/user`, `/key`, `/credits`), TeamoRouter (`/models/config`, `/billing/me/balance`) и PlusVibe (`/v1/pricing`, `/v1/balance`). Цены и баланс всегда отображаются в валюте аккаунта (USD, ₽).
- Панель «Аккаунты провайдеров» в GUI: состояние `live`/`stale`/`unsupported`, остаток средств, валюта, число моделей с подтверждённой ценой и время последней проверки.
- Ключ провайдера разрешается серверной частью через сохранённые в OpenCode connections и отправляется только на зафиксированные в коде API-origin; настройки провайдера не могут перенаправить запрос. Ключи не отображаются в GUI, не передаются через RPC и не попадают в статус.
- Обновление аккаунтов по событиям `provider.updated`, `model.updated`, `credential.updated`, `credential.switched`, `integration.updated` и `config.updated`.
- Стратегия `cheapest` и сортировка/группировка цен учитывают валюту: смешанные валюты никогда не сравниваются численно и не конвертируются по предполагаемому курсу; фактическая стоимость шагов OpenCode (USD) не переинтерпретируется в валюту аккаунта.
- Регрессионные тесты парсеров аккаунтных API, отсутствия credentials, `stale`-кэша, `unsupported`-аккаунтов и RUB/USD-маршрутизации; live-тест проверяет аккаунтные снапшоты и отсутствие ключей в RPC-выводе.

### Изменено

- Публичный агрегатор `models.dev` и `curl`-fallback удалены: цены берутся только из аккаунтных API. Для моделей без подтверждённого аккаунтного тарифа цена не показывается и не угадывается; native-цены OpenCode больше не используются как fallback.
- PlusVibe: тарифы берутся из аутентифицированного `/v1/pricing` и маппятся только на объявленный вариант по умолчанию; неиспользуемый эндпоинт `/v1/billing` не вызывается.
- При ошибке обновления предыдущие аккаунтные данные сохраняются и помечаются `stale` вместо подмены публичными ценами.

## [0.2.0] - 2026-10-30

### Добавлено

- Settings page и команда OpenCode Desktop через `gui-experimental`: полный каталог моделей, поиск, сортировка и пять способов группировки.
- Сохраняемые через server storage настройки GUI, реальные переключатели роутинга и `disabledModels` без изменения credentials провайдеров.
- Выбор любой разрешённой модели и variant для открытой сессии без отправки prompt, включая модели вне route-групп.
- Редактор ручных групп с разными model ID, variant, стратегиями, приоритетами и группой по умолчанию.
- RPC `configure`, эффективные настройки и полный инвентарь в `status`; bundle-, catalog- и configuration-тесты.
- Актуальные тарифы `models.dev` с ETag-ревалидацией, отображением источника и времени обновления; живые цены участвуют в сортировке и стратегии `cheapest`.
- Fallback на цены OpenCode и статус `stale`/`unavailable`; неизвестные цены остаются `—`. Для сетевых ошибок Node fetch добавлен fallback на системный `curl` без передачи credentials или prompt.

### Исправлено

- Изменение и загрузка сохранённого `rescanIntervalMs` пересоздают таймер без перезапуска; cleanup не позволяет воссоздать его из отложенной настройки.
- Отключённая текущая модель сохраняется для lookup группы, но не выбирается, поэтому возможен переход на доступную альтернативу.
- GUI использует server и `location` выбранной сессии для всех RPC; переименование группы по умолчанию обновляет `defaultGroup`.
- Конфигурация сразу перестраивает группы из кэша, а выключение роутинга отменяет ожидающее synthetic-продолжение, включая незавершённый failover.
- Необязательные поля RPC корректно проходят строгую валидацию реального сервера.
- Live-тест использует изолированный сервер, поэтому не зависит от entrypoint-кэша уже запущенного фонового процесса.
