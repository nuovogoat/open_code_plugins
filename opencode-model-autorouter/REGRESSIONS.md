# REGRESSIONS — реестр багов и покрывающих их тестов

Каждый пункт фиксирует инцидент, версии и ссылку на тест, который ловит баг
(стандарт §10, регрессионный гейт §8.2 — `test/regressions.test.ts`: пункт без
ссылки на реально существующий тест не принимается; новые баги замороженных
версий добавляются сюда вместе с тестом).

Формат ссылки: `` - Тест: `test/файл.ts` — «точное имя теста» ``.

## R-001 — Молчаливая подмена явно выбранной модели

- Инцидент: prompt-hook роутера подменял модель по умолчанию
  (`plusvibe/qwen3.8-max` → `apimaster/…`) на каждом запросе; владельцу
  пришлось отключать плагин целиком вместо точечной настройки.
- Версии: дефект до v0.7 включительно, исправлено в v0.8.0
  (`askBeforeOverride`: вопрос вместо перехвата, ответ «оставить» закрепляет
  выбор, failover остаётся молчащим, но видимым).
- Тест: `test/router.test.ts` — «manual choice: router asks before overriding and keep pins the manual model»
- Тест: `test/router.test.ts` — «manual choice: askBeforeOverride=false keeps fully automatic silent routing»

## R-002 — Опечатка «opecode» в имени собственном

- Инцидент: пропущенная «n» в ID плагина (`opecode-model-autorouter`) прожила
  шесть релизов — в командах установки, RPC-путях и Git-теге; нашёл владелец,
  а не гейт.
- Версии: исправлено в v0.7.0 (ломающее переименование, `3cd19b4`); канон
  написания закреплён тестом-пином, переименование ID — всегда бамп версии.
- Тест: `test/version.test.ts` — «name: every identifier uses the canonical product spelling»

## R-003 — `__proto__`-ключи в записях настроек

- Инцидент: пользовательские записи `providerSites`, `groups`,
  `accountThresholds`, `priceLimits` с ключом `__proto__` могли прототипно
  загрязнять нормализованные опции роутера.
- Версии: исправлено в v0.6.0 (нормализация отбрасывает `__proto__` и пустые
  ключи, `providerSites` ограничены 50 записями).
- Тест: `test/robustness.test.ts` — «robustness: garbage providerSites are normalized away, prototypes stay clean»
- Тест: `test/robustness.test.ts` — «robustness: absurd configure patches are normalized, not fatal»

## R-004 — Выдумывание цен из нераспознанного формата

- Инцидент: публичный листинг без цен чуть не стал «источником тарифов» —
  значение, которого API не возвращал, было бы выдумано интерпретацией.
- Версии: правило «нераспознанное — не данные» введено в v0.3 и окончательно
  закреплено в v0.6 (распознаётся только документированная структура ответа;
  нераспознанный формат даёт пустой результат).
- Тест: `test/pricing.test.ts` — «public pricing: only recognized shapes are parsed, nothing is invented»

## R-005 — Обрезание сверхдлинного URL вместо отклонения

- Инцидент: слишком длинный адрес публичного источника укорачивался молча —
  обрезание меняет смысл адреса и подменяет источник.
- Версии: исправлено в v0.6.0 (невалидный или сверхдлинный вход отклоняется
  целиком, а не обрезается).
- Тест: `test/pricing.test.ts` — «public pricing: site validation accepts https and loopback only, strips credentials»

## R-006 — backoff не сбрасывался при исправлении адреса

- Инцидент: исправленный адрес публичного API не проверялся ~30 минут из-за
  backoff, поставленного прежним адресом; герметичные тесты дефект не поймали
  — его поймал только live-тест.
- Версии: исправлено в v0.7.0 (`3cd19b4`): кэш и таймеры повторных попыток
  привязаны к входу и сбрасываются при его изменении (§4.6).
- Тест: `test/router.test.ts` — «public pricing: a changed site address is probed immediately despite failure backoff»

## R-007 — GUI рисовал кнопку аккаунтного ключа провайдерам без аккаунтного API

- Инцидент: кнопка «Аккаунтные цены и баланс» в панели «Публичные цены без
  входа» предлагала сохранить ключ провайдерам без подтверждённого аккаунтного
  API — настройка без потребителя (§4.5).
- Версии: дефект с рефакторинга «без хардкода» (`e679071`), исправлено в
  v0.8.1 (`52aa77d`): кнопка гейтится живыми capability
  (`pricingSupported`/`balanceSupported`) из единого источника истины.
  Герметичный тест покрывает capability-контур, которым питается гейт кнопки.
- Тест: `test/pricing.test.ts` — «accounts: providers without a confirmed account API stay unsupported without requests»

## R-008 — RPC `setAccountKey` принимал ключ провайдера без аккаунтного API

- Инцидент: ключ для `apimaster` сохранялся в сейф, хотя отправлять его некуда
  (ключи ходят только на фиксированные origin аккаунтных API) — мёртвая
  настройка; GUI-гейт R-007 не покрывал RPC-контур. Найден жёстким
  live-прогоном реальным CLI, который не входит в герметичную сюиту.
- Версии: дефект с `e679071`, исправлено в v0.10.1 (`736c675`):
  `accountCapable` отклоняет до записи в сейф — единый источник истины с GUI.
- Тест: `test/router.test.ts` — «vault: setAccountKey rejects providers without a confirmed account API even when rostered»
